## 1. 成品层状 NCM（R-3m，No.166，Hall `-R 3 2"`）

### 1.1 COD 1520789（NCM811，首选）

`_chemical_name_systematic`: `(Li0.98 Ni0.02) (Li0.05 Ni0.75 Co0.1 Mn0.1) O2`

原子占位（原文逐行、逐列核验）：

| label | 元素 | x | y | z | occ | 所属层 |
|---|---|---|---|---|---|---|
| `Li1` | Li | 0 | 0 | **0.5** | 0.98 | **Li 层** |
| `Ni1` | Ni | 0 | 0 | **0.5** | 0.02 | **Li 层**（混排） |
| `Ni2` | Ni | 0 | 0 | **0** | 0.75 | **TM 层** |
| `Co1` | Co | 0 | 0 | **0** | 0.10 | **TM 层** |
| `Mn1` | Mn | 0 | 0 | **0** | 0.10 | **TM 层** |
| `Li2` | Li | 0 | 0 | **0** | 0.05 | **TM 层**（额外 Li） |
| `O1` | O | 0 | 0 | 0.259 | 1.00 | 6c |

**读法**：Li 层（z=0.5）= Li0.98 + Ni0.02 → **2% Li/Ni 混排**；TM 层（z=0）=
Ni0.75 + Co0.10 + Mn0.10 + Li0.05。总 Li = 0.98+0.05 = 1.03，总 Ni = 0.02+0.75 = 0.77，
与 `_chemical_formula_sum 'Co0.1 Li1.03 Mn0.1 Ni0.77 O2'` 完全自洽。

> ⚠ **位点命名陷阱（务必注意）**：按 International Tables 的 R-3m 标准取法，
> **3a 是 (0,0,0)、3b 是 (0,0,1/2)**。本 CIF 把 **Li 层放在 z=0.5、TM 层放在 z=0**，
> 相当于取了另一套原点，因此**不能**按 z 值直接叫作「3a = Li 层」。
>
> **代码约定（写入 T3.1）**：识别 Li 层/TM 层一律**按占位内容判定**
> （Li 占位最高的那个 3 重位 = Li 层），**不看 z 坐标、不硬编码 3a/3b**。
> 报告里同时给出「实测 z 坐标」与「Wyckoff 多重度」两个客观量，避免原点选择歧义。

## 4. 规范化说明（重要）

COD 原始 CIF 有两种书写习惯会让家族解析器失效：

| 现象 | 例子 | 家族解析器行为 |
|---|---|---|
| 数值带 esd 括号 | `_cell_length_a 3.1268(1)` | `float()` 失败 → **晶胞退化为 1.0** |
| 原子坐标带 esd | `O1 ... 0.2153(4)` | `_to_float` 返回 None → **该原子被静默丢弃** |
| 原子 loop 多余列 | `symmetry_multiplicity` / `Wyckoff_symbol` / `attached_hydrogens` | 列数不符时可能整行跳过 |

实测：`precursor_NiOH2.cif` 原样送入解析器只得到 **1 个原子**（应为 5 个），
`|F|²` 全错且**不报错**——这是最危险的一类缺陷。

**内置 CIF 的处理**：`tools/build_cif_pack.py` 写入时调用 `normalize_cif_text()`，
只改书写形式、**不动任何数值**：
1. 去掉晶胞/原子数值的 esd 括号（`3.1268(1)` → `3.1268`）；
2. 原子 loop 重排为 7 列标准集（label / type_symbol / fract_x / fract_y /
   fract_z / occupancy / U_iso_or_equiv），丢弃解析器不读的列。

`INDEX.json` 同时记录 **规范化后 sha256** 与 **COD 原始文件 sha256**（`cod_sha256`），
可逐份回溯到原始字节。

**用户导入 CIF 的同类问题**：由任务卡 **T1.2b（CIF 解析器健壮性加固）** 在解析器层
解决，不依赖用户手上的文件是否规范化。
